# Architecture

```
            ┌──────────────────────── MoonClubApp (composition root) ───────────────────────┐
            │  live:  LiveMarketData · LunaRouter · LiveVoice · SharedProgressStore · SystemClock│
            │  -demo: FakeMarket     · LunaRouter · FakeVoice · MemoryStore       · FixedClock│
            └───────────────────────────────┬───────────────────────────────────────────────┘
                                            │ Services (protocols)
                                   ┌────────▼────────┐   intents    ┌──────────────────────┐
   SwiftUI Features  ──reads────▶  │    AppModel     │ ───────────▶ │ KidsState reducers   │
   (Story, Guess, Piggy,  ◀─────── │  @Observable    │ ◀──new state │ (pure, MoonClubCore) │
    School, Quests, Luna, ...)     └────────┬────────┘              └──────────────────────┘
                                            │ derived: points, level, badges, recap, chapters
                                   ┌────────▼────────────────────────────────────────────┐
                                   │ MoonClubCore: content model + validation, logic,     │
                                   │ League codec, quest math, LayeredCache, requests     │
                                   └──────────────────────────────────────────────────────┘
        kids-content.json  ◀── metaphases `npm run export:kids` (content + test vectors)
```

| Principle | Where |
|---|---|
| **Single source of truth** | Content comes only from `kids-content.json`, exported from the web repo. `VectorTests` proves the Swift logic matches the web's for every exported vector. |
| **Separation of concerns / decoupling** | `MoonClubCore` imports Foundation only (no UIKit/SwiftUI) and builds and tests on macOS. Every outside boundary is a protocol in `Services.swift`: `MarketDataSource`, `LunaService`, `VoiceService`, `ProgressStore`, `Clock`. |
| **Dependency injection** | `MoonClubApp.boot()` is the only place that picks live or fake implementations. Views get the one `AppModel` from the environment; there are no singletons beyond the composition root (plus the debug-only `FrameProbe`). |
| **Unidirectional data flow** | Views send intents (`app.mutate { $0.guess(...) }`). Pure reducers on `KidsState` return the new state. `AppModel` persists it atomically and views re-render from derived values. |
| **Pure functions, testability** | All logic is a pure function of its inputs: dates are ISO strings, and `Clock` is injected so tests use a fixed day. |
| **Errors as values** | `KidError` carries friendly copy. Content loading returns a typed `LoadError` (unsupported version, invalid), shown by `ContentErrorView` instead of a crash. |
| **Versioned, schema-validated content** | `KidsContent.load` checks `version` and then `validate()`: unique ids, units exist, answers in range, sorts have 2 buckets, ≤ 32 companies (5-bit League codes), levels ascending. |
| **Caching** | `LayeredCache`, layered memory → disk (LRU, byte cap) → network, with per-endpoint TTLs and stale-while-revalidate. If the network fails, it serves the last good copy (up to `maxStale`). A `Coalescer` keeps one load in flight per key. Luna answers are cached for 7 days, keyed by the normalized question plus the content version. Voice clips are cached on disk by text and voice (24 MB LRU). |
| **Luna's brains** | `LunaService` is a `LunaRouter` (MoonClubCore `Brain.swift`) over three `LunaBrain`s: `OnDeviceBrain` (FoundationModels, iOS 26+, nothing leaves the device), `FreeBrain` (the Metaphases free model, no key), `ByokBrain` (a grown-up's own Anthropic/OpenAI/Gemini/xAI key, sent straight to the provider). `BrainRouter.resolve` is pure: automatic = on-device when available, else free; BYOK needs a key **and** consent for that provider, or it falls back. The router re-resolves on every question, builds one `LunaPrompt` (same kid-safe system prompt, mirrored from the web's `KIDS_SYSTEM`), and streams **guarded cumulative snapshots** through `LunaGuard` (link stripping, a length cap per brain, and a blocklist → gentle redirect, applied mid-stream). `BrainCapabilities` says what each brain unlocks: memory turns, "Explain more", length. Settings live in UserDefaults (`moonclub.brain.v1`); the key lives only in the Keychain (`…lunakey`). |
| **Safety rules as code** | `Requests.luna` has no key parameter at all. `Requests.byok` returns nil unless the saved consent is for that provider. `Requests.speak` returns nil for kid-typed text (`SpeakSource.mayUseKey`). `scripts/check-rules.sh` allows a key header only inside `Requests.byok` / `models` / `speak`, forbids hard-coded consent, and forbids links out and `openURL` outside `GrownUps.swift`, remote packages and analytics SDK imports. Unit tests cover the request builders. |
| **Performance** | `AuroraField` is one full-screen Metal `colorEffect` layer at ≤ 30 fps (`TimelineView(.animation(minimumInterval:))`), with no textures and no per-frame allocations. It pauses off-screen, in the background and in Low Power Mode, and shows a still frame under Reduce Motion. A debug `FrameProbe` logs the average frame interval every 120 frames (Console, category "aurora"). Celebrations are drawn in a single `Canvas`. |
| **Widgets & Live Activities** | A `MoonClubWidgets` app extension: five widgets (Report Card Day, Market Weather, Pretend Piggy Bank, Moon School, Luna's Moon), each in the families it makes sense for (Home Screen small/medium/large; Lock Screen and StandBy accessory circular/rectangular/inline), plus one Live Activity (`MoonActivityAttributes`: Report Card Day, Lesson in progress). **Data flow:** `AppModel.mutate` / `loadMarket` → `WidgetPublisher.publish` builds a `WidgetSnapshot` (pure, MoonClubCore `Widgets.swift`; < 2 KB; only app content, small numbers and dates, enforced by a key-allowlist test). It writes to a shared keychain group (`Shared/MoonShare.swift`) **only if the bytes changed**, then reloads timelines. The provider reads that one item: no network, no content decoding. `WidgetTimeline.entryDates` emits only the moments the look changes (now, each report time today, midnight); countdowns are `Text(timerInterval:)`, so the system ticks them without timeline churn. **Touch:** interactive buttons are App Intents (`Shared/MoonIntents.swift`) that write the optimistic snapshot first, then the progress item; the widget redraws from the snapshot as soon as the intent returns (`invalidatableContent` covers the gap). **Live Activities** are local only (`pushType: nil`, enforced by `check-rules.sh`). The report activity's `staleDate` is the report time, so it flips itself to "Results are in!" via `context.isStale` with no update. **Deep links:** `moonclub://tab/<tab>` and `moonclub://lesson/<id>` route through `AppModel.open` (only our scheme). **Why keychain, not an App Group:** every team profile already allows `<TeamID>.*` keychain groups, while App Groups need portal setup the App Store Connect API can't do. Items are `AfterFirstUnlockThisDeviceOnly` (lock-screen readable, never synced). |
| **Accessibility** | Dynamic Type throughout (system text styles); VoiceOver labels on every custom control; 44pt targets; Reduce Motion respected by aurora, particles, transitions and Luna's bob/blink. |
| **Sync across devices** | Opt-in, per device, behind the gate ("Your devices" in the grown-up corner). `SyncService` has three implementations: `ICloudSync` (`NSUbiquitousKeyValueStore`, one JSON value at `progress.v1`), `DemoSync` and `NoSync`. The only path is the family's iCloud account; we run no sync server. The merge lives in MoonClubCore `Sync.swift`: `KidsState.merged(with:)` is a join (commutative, associative, idempotent; property-tested over 400 generated states), so devices converge whatever the order or repetition. Lessons, badges and quest stages are unions, and a lesson keeps its earliest date. Guesses have one entry per company and day: the more-resolved one wins, then the later edit, then a fixed tiebreak. For the piggy bank, the later `started` wins outright; with the same start, history is a union by day. The league is a union by emoji, and `leaguePlayers` hides "me" when it's read. Points, level and badges are always derived, never summed. **Reset on all devices** bumps `resetEpoch`, and a higher epoch beats every older copy. **This device only** keeps the epoch and turns sync off on that device. `Sync.payload` drops device-only fields (`recapSeen`) and keeps at most 400 guesses and 200 KB, far under the 1 MB limit. `AppModel.commit` is the one place state changes: it saves, pushes (debounced 1.5 s), then calls `stateDidChange()`, which is where widgets republish their App Group snapshot. Merges from other devices arrive through `didChangeExternallyNotification` → `absorb`. |
| **Own key on other devices** | Optional "Use on my other devices" (default off) moves Luna's own key **and** its settings (provider, the grown-up's consent for that provider, model) through iCloud Keychain (`kSecAttrSynchronizable`), never through key-value sync. On the other device `BrainStore.load()` adopts them via `KeyTravel.adopt`, unless a grown-up there already chose a different provider. Removing the key, or changing provider, deletes it everywhere along with its consent. |
| **Move my progress (web → app)** | The website's grown-up corner makes a `MOONP1-…` code: base64url of a compact JSON with only ids, days, picks and numbers, plus a 4-character FNV checksum (metaphases `shared/kidsTransfer.ts`). The app decodes it with `Transfer.decode` and merges it in, so pasting twice is harmless. Both sides are pinned by the `transfer` vectors from `npm run export:kids`. There's no camera, no QR scanner and no Universal Link: a grown-up copies and pastes. |

| **Market World (the map)** | The World tab (replacing Moon School's list; the list is one tap away in the map header). **Rules are pure** in MoonClubCore `World.swift`: seven `Region`s (Lemonade Coast, Saver's Isle, Candle Canyon, Trend Trails, Pattern Peaks, Signal Sea, Report Card Castle) of `WorldNode`s (a unit trail, a lesson, a quest chapter, a chart game, Guess the Report Card, or a boss: a review quiz or the Chart Time Machine). Stars (0–3) come from finished lessons and quests, or are stored per node in `KidsState.stars` (best ever; merged as a per-node max in `Sync.swift`). A land opens when the one before it is conquered (its boss has a star); a stop opens when the stop before has a star. Map points are 5 per game/boss star, added in `KidsState.points`. Nodes whose content isn't in this build are dropped. **Charts are pure** in `Charts.swift` (`ChartMath`: least-squares trend, floor/ceiling bands, SMA, busiest day, day stories, star scoring; `Practice` makes seeded textbook patterns, labeled "practice chart"). Real candles: a bundled year (`Resources/candles.json`, 8 kid-known companies) refreshed from metaphases `/api/kids/candles` in the live app; demo mode stays on the bundle. **Drawing:** the sea, islands and trail are one `Canvas` (`drawingGroup`) redrawn only when progress changes; stops, banners, landmarks and fog are views placed by the `MapPlacement` Layout (each at its real frame, so `scrollTo` and hit-testing work); cloud parallax is `visualEffect` (no state writes while scrolling). Games share `GameShell` (rounds → feedback → stars) and one `CandleChart` Canvas. |
| **Art and motion** | One illustration language (`Design/Art.swift`): content still names things with emoji (the web's art), but the app maps every emoji key to an SF Symbol + a `Hue`, drawn as a `Glyph` tile / halo / plain, with a few drawn marks where no symbol fits (`CandleMark`, `PiggyMark`). Shared by the app, widgets and Live Activities. `CardFitTests` checks every symbol exists and every content emoji has art. **Motion** (`Design/Motion.swift`): five tokens (`tap`, `card`, `page`, `celebrate`, `gentle`), all swapped for a short fade under Reduce Motion; `enterOnce` runs an appear animation once per session (not on every tab switch). The old forever-looping `phaseAnimator` pulses on emoji were removed. |
| **No scrolling inside cards** | Pages may scroll; cards never do. Lessons: the card grows to its content (at least the screen), buttons pinned in a bottom inset. Story: a paging row as tall as its tallest card (not lazy, so swiping never jumps). Sort games are a one-card-at-a-time deck. Enforced by `CardFitTests` (every lesson step at iPhone SE / 17 / Duo outer / iPad at xxxLarge text, plus a source check that card views contain no `ScrollView`) and the MoonClubCore content lint (`WorldTests.testEveryCardStepFitsOneCard`). |
